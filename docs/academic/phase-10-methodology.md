# Phase 10 Academic Methodology

Phase 10 applies requirements-based verification to the completed functional layers. Verification
is separated into unit, integration, API, cross-layer scenario, React interaction, migration,
build, and manual interface evidence. A maintained mapping connects each implemented requirement
to concrete tests and review artifacts.

The principal defence scenario uses a fictional emergency pathway. It begins with registration,
continues through one-question-at-a-time fact collection and immediate red-flag escalation, and
ends with deterministic inference, an immutable PDF, filtered history, ownership denial, and
audit evidence. A separate governance scenario demonstrates patient/administrator separation,
knowledge validation, publication, retention, rollback, and historical reproducibility.

Backend coverage is measured across the application package with a 90% minimum gate. Coverage is
treated as evidence of exercised code, not proof of correctness. React tests focus on semantic
roles, accessible names, safety prominence, state restoration, stale-update recovery, API
failure recovery, and role-specific navigation. Manual inspection remains necessary for
responsive layout, keyboard order, visible focus, contrast, print layout, and the live
demonstration narrative.

The evaluation remains bounded by the academic prototype status. Passing verification confirms
software conformance to authored rules and contracts; it does not validate the knowledge base
clinically or establish diagnostic performance.
