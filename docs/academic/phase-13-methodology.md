# Phase 13 Academic Methodology

Phase 13 uses evidence-led documentation synthesis. Phase reports, architecture decisions,
source records, API implementations, tests, release evidence, and operational guides are treated
as the authoritative inputs. The synthesis does not infer clinical outcomes or invent a user
study. Every statement about implemented behavior is checked against accepted repository
evidence, while every medical-context claim remains linked to the source registry.

The final manuscript separates software conformance from clinical validation. Quantitative
results are limited to observed automated-test, coverage, build, and artifact evidence.
Institution-specific preliminary pages and citation presentation remain adaptable because no
departmental template has been supplied; verified titles, organizations, dates, URLs, and
retrieval dates remain fixed.

Reader documentation is organized by task: patients use the user guide, administrators use the
governance guide, developers use the development and testing guides, operators use the Windows
or server deployment guide, and examiners use the consolidated API, diagrams, academic report,
traceability matrix, and defence scenario. An automated integrity check validates required
documents, local links, academic headings, and source coverage so documentation regressions fail
the Phase 13 gate.
